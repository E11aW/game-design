# Persistent Storage
## Chosen Storage Method
I chose to store data for my little "organization game" using the built-in player preferences in Unity. I chose this for two main reasons: (1) it is a simiple solution for a very simple game and (2) I wanted to test this one out in a low-stakes environment since I'm sure my actual final project will need a more involved solution. I wanted to try out the options built into Unity since I want to learn a little more about the game engine too. The cons of this storage method is that the simplicity limits what can and cannot be stored. This was not too much of a hinderance with such a simple game, but for my final project I will probably need something more involved.
## Other Considered Storage Methods
While I knew from the beginning that I wanted to use the built-in player preferences, I did think on why. Some of the other mentions discussed in class like JSON files and definitely databases are far more involved and complex. While they offer a lot of flexibility and variability in storage options, it is far more than I need for the simple demo game I have been experimenting with on the side. I also wanted to be reasonable time-wise with all my other commitments over the weekend; it would have been unwise to spend so many hours on this instead of the final projects. I feel as though I still gained a much better understanding of persistent storage through exploring the built-in player preferences and can later on experiment more with these more involved options when working on my final project with my group.
